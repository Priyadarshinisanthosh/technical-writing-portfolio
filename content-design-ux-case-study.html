Creating One Coherent Language System Across Seven Creation Tools

Portfolio simulation: “Canvas Suite,” its product strings, research findings, and metrics are fictional. This sample demonstrates my UX-writing and content-design process and does not reproduce Google Workspace interfaces.

The Product Challenge

Seven product teams—documents, spreadsheets, presentations, forms, sites, video, and images—have independently introduced templates, reusable content, and AI-assisted creation. The experiences are capable, but users encounter overlapping terms such as template, building block, component, scene, and module. Similar actions also use different verbs: add, insert, apply, place, and use.

The content-design goal is to create cohesion without flattening meaningful differences. The system must support expert workflows, first-time comprehension, localization, accessibility, and future AI capabilities.

I would begin with a string and journey audit, then combine it with research, support data, and product strategy.

Illustrative audit finding

Users understood “template” as a starting point for a new file, but three teams also used it for content inserted inside an existing file. This created uncertainty about whether applying a template would replace current work.

Taxonomy and Naming Architecture

I proposed a three-level hierarchy based on user intent rather than implementation:

  1. File: The primary creation artifact, such as a document, sheet, presentation, form, site, video, or image.
  2. Section: A meaningful structural region within a file, such as a slide, page, scene, question group, or sheet.
  3. Block: Reusable content inserted within a section, such as a table, chart, callout, question, or media element.

Surface-specific terms remain where they carry essential meaning. A slide is still a slide and a sheet is still a sheet. The shared hierarchy provides a governance layer for navigation, AI instructions, Help content, analytics, and design patterns.

End-to-End Content Design: Create From a Source

The target journey lets a user turn existing source material into a new artifact while maintaining control.

StageUser questionContent responsibility
EntryWhat can I make?Name the outcome and eligible sources
Set upWhat will the system use?Show scope, selected sources, and optional instructions
GenerateIs it working?Communicate progress without overstating quality
ReviewIs this ready?Present a draft, sources, uncertainty, and revision options
CommitWhat happens next?Name whether the result is inserted, replaces content, or creates a file
RecoverCan I reverse it?Provide undo, version history, and clear failure recovery

High-Visibility Product Microcopy

Entry point

Label: Help me create

Supporting text: Start with a goal, a source, or both. You will review a draft before adding it to your work.

Source selection

Label: Add sources

Helper text: Choose files or selected content to guide the draft. People with access to the result may not have access to every source.

Ambiguous request

What should the summary focus on?
Options: Key decisions · Action items · Full overview

Revision feedback

Updated the tone and shortened the first two sections. Your original draft is available in version history.

High-impact confirmation

Replace the selected content? This will remove 6 slides and insert the new draft. You can undo this change.

Recovery error

Couldn’t create the draft from one source. Remove the unavailable source or request access, then try again.

Why these choices

  • Actions name the visible result instead of using generic verbs such as Submit or Done.
  • Scope and reversibility appear before consequential changes.
  • Errors distinguish access, input, model, and system problems so recovery is specific.
  • AI output is called a draft to support appropriate review rather than false certainty.

Research, Accessibility, and Measurement

I would test the conceptual model before polishing strings. Participants would complete matched tasks across multiple surfaces so we can measure whether terminology transfers.

  • Tree testing: Can users locate templates, reusable blocks, and AI creation actions?
  • Concept testing: Can users explain the difference between Insert, Apply, Replace, and Create?
  • Moderated usability: Can users predict the result before committing a generated draft?
  • Longitudinal study: Does cross-suite familiarity reduce time and errors over repeated use?

Accessibility and localization requirements

  • Do not rely on color, animation, or visual placement alone to communicate AI state.
  • Announce progress, completion, and errors appropriately for assistive technologies.
  • Use explicit control labels and preserve keyboard focus after dynamic updates.
  • Design strings for expansion and avoid grammatical constructions that cannot localize cleanly.
  • Provide text alternatives and editable transcripts for generated visual and voice content.
  • Use plain language while preserving expert precision and domain terms.

Governance and Cross-Functional Alignment

I would use a taxonomy working group and a decision framework rather than relying on one-time string review.

Decision criterionQuestion

LongevityWill the pattern support planned AI and multimodal capabilities?

Artifacts include a controlled glossary, taxonomy map, pattern library, string decision log, research evidence, exception process, adoption dashboard, and executive narrative. Product, Engineering, Research, Accessibility, Localization, Legal, and Marketing participate at defined decision points.

Product narrative for alignment

Users should not need to understand seven organizational structures to create across seven tools. Our language system makes creation predictable while protecting the distinctive workflows that make each tool valuable.

Outcome

This case study demonstrates content design beyond isolated strings: auditing a product ecosystem, defining a scalable taxonomy, designing an end-to-end journey, writing precise microcopy, testing the mental model, setting KPIs, and establishing governance that can evolve with the platform.
