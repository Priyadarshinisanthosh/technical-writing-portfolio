Designing Product UI Content for an AI-Assisted Alert Builder

Portfolio Simulation: This is a fictional product scenario created to demonstrate content design, UX writing, and collaboration with product/design/research teams.

The Challenge

Users need to create an alert rule by choosing a signal, condition, delivery channel, and recipients. The initial UI uses engineering language such as condition type, operator, trigger expression, and notification target. The content goal is to reduce cognitive load without removing necessary technical precision.

Questions I Would Resolve with Design and Research

  • What mental model do users bring to alert creation?
  • Which terms do users already recognize from the product?
  • Where do users abandon or misconfigure the workflow?
  • Which fields need inline explanation versus progressive disclosure?
  • What information is essential before users click Create?
  • Which error states can be prevented through better labels or examples?

Content Design for the Flow

Engineering labelUX contentReason
Trigger ExpressionWhen should this alert run?Frames the field as a user goal.
Notification TargetWho should be notified?Uses familiar language and clarifies intent.
Channel TypeHow should we notify them?Turns a system attribute into a decision.
Execution FrequencyHow often should we check?Clarifies that frequency controls evaluation, not delivery volume.

Sample Product UI Microcopy

Page title

Create alert

Get notified when activity in your workspace matches the conditions you choose.

Alert name

Label: Alert name

Helper text: Use a name your team will recognize, such as “Production export failed.”

Condition

Label: When should this alert run?

Example: Job status is Failed

Recipients

Label: Who should be notified?

Helper text: Add people or groups with access to this workspace.

Primary action

Create alert rather than Submit, because the button should describe the result of the action.

Empty, Success, and Error States

Empty state

No alerts yet. Create an alert to get notified when important activity needs your attention.

Success message

Alert created. We'll notify the selected recipients when the conditions are met.

Duplicate-name error

An alert with this name already exists. Choose a different name.

Invalid recipient

We couldn't add this recipient. Check the email address or choose someone with workspace access.

Unsaved changes

Discard your changes? Your alert hasn't been created yet.

Content Principles Applied

  • Action first: Labels describe the decision users need to make.
  • Progressive disclosure: Technical details appear only when they help complete the task.
  • Consistent terminology: One user-facing term is used for each concept across labels, errors, and Help content.
  • Prevent errors: Helper text and examples address common mistakes before validation.
  • Explain outcomes: Confirmation content tells users what the system will do next.

Outcome

This case study demonstrates how I would work as an embedded content designer: identify user decisions, align terminology with research and product models, design microcopy across the complete interaction, and treat empty, error, confirmation, and recovery states as part of the product experience rather than as afterthoughts.
