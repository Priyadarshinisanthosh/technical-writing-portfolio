Designing Trustworthy AI Creation Across Seven Product Surfaces

Portfolio simulation: “Canvas Suite” and all research findings, model behavior, metrics, and interface examples are fictional. This case study demonstrates my approach to AI content strategy; it does not describe Google products or confidential work.

Product Brief and Strategic Problem

A productivity suite is adding generative AI to seven creation surfaces: documents, spreadsheets, presentations, forms, sites, video, and images. Each team has designed useful features, but users encounter different names, prompts, progress messages, and revision behaviors for the same underlying actions.

The content strategy must preserve familiar creation workflows while establishing a scalable AI interaction model. The goal is not to make every surface identical. It is to make the underlying concepts predictable enough that learning transfers from one product to another.

Shared Mental Model: Ask → Plan → Create → Refine → Apply

I proposed one cross-suite model that can flex by surface:

  1. Ask: The user describes the goal and may add source context.
  2. Plan: For broad or high-impact requests, the system confirms scope or proposes an outline.
  3. Create: The model generates a draft while communicating progress.
  4. Refine: The user revises through direct editing, follow-up prompts, or structured controls.
  5. Apply: The user deliberately inserts, replaces, or publishes the result.

This framework separates generation from commitment. It supports a quick path for low-risk actions while adding confirmation for destructive, ambiguous, or wide-scope changes.

System-Instruction Content Architecture

I would structure instructions as a governed hierarchy, separating durable product principles from surface-specific behavior. This reduces contradictions and makes changes traceable.

ROLE
Help users create and revise content while preserving their intent,
control, and ability to review changes.

PRIORITIES
1. Follow the user's stated goal and selected scope.
2. Do not claim that generated content is verified or complete.
3. Preserve source meaning unless the user asks to transform it.
4. Never imply that a draft has been inserted, sent, or published
   until the product confirms that action.

BEHAVIOR
- Ask one focused question when missing context would materially
  change the result.
- For broad changes, summarize the proposed scope before applying.
- Distinguish model uncertainty from a system or connection error.
- Offer a useful revision path after partial or low-confidence output.
- Use the suite terminology glossary and surface-specific action label.

OUTPUT
Use concise product language. Match the format to the creation surface.
For voice or visual input, confirm the interpreted intent when ambiguity
could create a high-impact change.

Research and Evaluation Plan

I would partner with Research, Data Science, Product, and Engineering to test comprehension and behavior—not only string preference.

  • Comprehension study: Can users predict what Insert, Replace, and Apply will change?
  • First-use usability: Can users generate, refine, and safely apply a result without coaching?
  • Recovery testing: Do users understand uncertainty, partial success, and model versus system errors?
  • Cross-surface transfer: Does learning the flow in one editor improve success in another?
  • Accessibility review: Are state changes announced, actions keyboard accessible, and generated media supported with text alternatives?

Suite Governance and Executive Alignment

I would establish a cross-suite content council with representatives from Product, UX, Research, Engineering, Accessibility, Localization, Legal, and Marketing. The operating system would include:

  • A shared taxonomy and decision log with owners, rationale, and affected surfaces.
  • Reusable content patterns for prompting, progress, uncertainty, revision, apply, and recovery.
  • A review matrix distinguishing global principles from local product decisions.
  • Quarterly audits using product strings, research signals, support themes, and model evaluation failures.
  • An escalation path for conflicts involving user trust, legal risk, accessibility, or platform consistency.

Executive narrative

Consistency is not identical wording. It is a transferable model of control: users know what the AI is doing, what will change, how certain the result is, and how to revise or undo it—regardless of the creation surface.

Outcome

The deliverable is a scalable AI content system: a shared mental model, naming architecture, system-instruction hierarchy, model-state heuristics, multimodal feedback framework, measurement plan, and governance process. Together, they support useful innovation without asking users to relearn trust and control in every product.
